SQL:
SELECT s.name, ROUND(AVG(g.marks_obtained),2) AS average_marks

Q2(c) Students with attendance below 75%
SQL:
SELECT s.name,
       ROUND(100 * AVG(a.status IN ('Present','Late')),2) AS attendance_pct
FROM Students s

HAVING attendance_pct < 75

Q3. SQL OPERATORS AND, OR, NOT
------------------------------------------------------------

Q3(a) Students with attendance below 50% AND failing (marks below 40)
SQL:
SELECT s.name,
       ROUND(100*AVG(a.status IN ('Present','Late')),2) AS attendance_pct,
       MIN(g.marks_obtained) AS lowest_marks
FROM Students s
JOIN Attendance a ON s.student_id=a.student_id
JOIN Grades g ON g.student_id=s.student_id
GROUP BY s.student_id, s.name
HAVING attendance_pct < 50 AND lowest_marks < 40;

Reason:
AND requires both conditions to be true. With the supplied sample data, no student satisfies both conditions, so output is Empty set (0 rows).

Q3(b) Students who scored above 90 OR have perfect attendance
SQL:
SELECT s.name,
       MAX(g.marks_obtained) AS highest_marks,
       ROUND(100*AVG(a.status IN ('Present','Late')),2) AS attendance_pct
FROM Students s
LEFT JOIN Grades g ON g.student_id=s.student_id
LEFT JOIN Attendance a ON a.student_id=s.student_id
GROUP BY s.student_id, s.name
HAVING MAX(g.marks_obtained)>90
    OR attendance_pct=100;

Reason:
OR returns rows when either condition is true. DISTINCT aggregation may be needed if joining multiple one-to-many tables in larger datasets; this query is suitable for the small supplied data, but the joins can duplicate rows in larger datasets.

Q3(c) Faculty NOT assigned to any course
SQL:
SELECT f.faculty_id, f.name
FROM Faculty f
WHERE NOT EXISTS (
  SELECT 1 FROM Courses c
  WHERE c.faculty_id=f.faculty_id
);

Reason:
NOT EXISTS returns faculty for whom no matching course exists.
output from the supplied sample data: Empty set (0 rows), because both listed faculty members are assigned to at least one course.

Q7(d) Students without grades using FULL OUTER JOIN equivalent
SQL:
-- MySQL has no direct FULL OUTER JOIN syntax.
SELECT s.student_id, s.name, g.course_id, g.marks_obtained
FROM Students s
LEFT JOIN Grades g ON g.student_id=s.student_id
WHERE g.grade_id IS NULL
UNION
SELECT s.student_id, s.name, g.course_id, g.marks_obtained
FROM Grades g
RIGHT JOIN Students s ON s.student_id=g.student_id
WHERE s.student_id IS NULL;

Reason:
FULL OUTER JOIN normally keeps unmatched rows from both sides. Since Grades.student_id is a foreign key, grade rows cannot refer to nonexistent students; the practical requirement “students without grades” is handled by LEFT JOIN alone.

Simpler and recommended query:
SELECT s.student_id, s.name
FROM Students s
LEFT JOIN Grades g ON g.student_id=s.student_id
WHERE g.grade_id IS NULL;

output for sample data: Empty set (0 rows), because each student has at least one grade.

Q11. WINDOW FUNCTIONS
------------------------------------------------------------

Q11(a) Rank students based on overall/average marks
SQL:
WITH averages AS (
  SELECT s.student_id, s.name, AVG(g.marks_obtained) AS avg_marks
  FROM Students s
  JOIN Grades g ON s.student_id=g.student_id
  GROUP BY s.student_id, s.name
)
SELECT name, ROUND(avg_marks,2) AS average_marks,
       RANK() OVER (ORDER BY avg_marks DESC) AS student_rank
FROM averages
ORDER BY student_rank;

Reason:
The CTE calculates one average per student. RANK() assigns rank 1 to the highest average. Tied averages receive the same rank and the next rank can be skipped.

output:
+--------------+---------------+--------------+
| name         | average_marks | student_rank |
+--------------+---------------+--------------+
| Aarav Sharma | 93.00         | 1            |
| Meera Joshi  | 87.00         | 2            |
| Rohan Shah   | 84.00         | 3            |
| Diya Patel   | 68.00         | 4            |
+--------------+---------------+--------------+

Q11(b) Cumulative attendance percentage per course
SQL:
WITH daily AS (
  SELECT course_id, attendance_date,
         SUM(status IN ('Present','Late')) AS attended,
         COUNT(*) AS total_records
  FROM Attendance
  GROUP BY course_id, attendance_date
)
SELECT c.course_name, d.attendance_date,
       ROUND(100 * SUM(d.attended) OVER (
         PARTITION BY d.course_id ORDER BY d.attendance_date
         ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
       ) / SUM(d.total_records) OVER (
         PARTITION BY d.course_id ORDER BY d.attendance_date
         ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
       ),2) AS cumulative_attendance_pct
FROM daily d
JOIN Courses c ON c.course_id=d.course_id
ORDER BY c.course_name, d.attendance_date;

Reason:
The window SUM accumulates attended and total records by course through each date. Dividing the cumulative counts gives the running percentage.

Q11(c) Running total of students enrolled per month
SQL:
WITH monthly AS (
  SELECT DATE_FORMAT(enrollment_date,'%Y-%m') AS enrollment_month,
         COUNT(*) AS new_enrollments
  FROM Enrollments
  GROUP BY DATE_FORMAT(enrollment_date,'%Y-%m')
)
SELECT enrollment_month, new_enrollments,
       SUM(new_enrollments) OVER (ORDER BY enrollment_month) AS running_total
FROM monthly
ORDER BY enrollment_month;

Reason:
The first query counts enrollments in each month. The window SUM adds each month to the total from previous months.

Q12(a) Assign performance levels
SQL:
SELECT s.name, c.course_name, g.marks_obtained,
       CASE
         WHEN g.marks_obtained > 90 THEN 'Excellent'
         WHEN g.marks_obtained BETWEEN 75 AND 90 THEN 'Good'
         ELSE 'Needs Improvement'
       END AS performance
FROM Grades g
JOIN Students s ON s.student_id=g.student_id
JOIN Courses c ON c.course_id=g.course_id
ORDER BY s.student_id, c.course_id;

Reason:
CASE checks conditions in order. More than 90 is Excellent; 75 through 90 inclusive is Good; anything else is Needs Improvement.

Q12(b) Categorize attendance records
SQL:
SELECT s.name,
       ROUND(100*AVG(a.status IN ('Present','Late')),2) AS attendance_pct,
       CASE
         WHEN 100*AVG(a.status IN ('Present','Late')) > 80 THEN 'Regular'
         WHEN 100*AVG(a.status IN ('Present','Late')) BETWEEN 50 AND 80 THEN 'Irregular'
         ELSE 'Defaulter'
       END AS attendance_status
FROM Students s
JOIN Attendance a ON a.student_id=s.student_id
GROUP BY s.student_id, s.name
ORDER BY s.student_id;

Reason:
CASE classifies each student's calculated attendance: over 80% Regular; 50% through 80% Irregular; below 50% Defaulter. This follows the assignment wording (“above 80%”, “between 50% and 80%”, “otherwise”).

output:

| Diya Patel   | 50.00         | Irregular        |
| Rohan Shah   | 100.00        | Regular          |
| Meera Joshi  | 100.00        | Regular          |
